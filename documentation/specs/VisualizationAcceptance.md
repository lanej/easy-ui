## Component boundaries

| Acceptance case                                            | Public surface / evidence                                                                                                                             |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Omitted title, omitted description, or external heading    | Optional independent props and standard ARIA associations on Chart and NetworkMap; naming/composition tests                                           |
| Geographic viewport without logistics placeholders         | Standalone `NetworkMapSurface`, or one surface under `NetworkMapProvider`, with no required facility/segment arrays                                   |
| Weather-only and surface-only compositions                 | Optional typed layers, applicable `NetworkMapControlPanel`/legend, complete `NetworkMapDataView`; LayerOnlyComposition story                          |
| External camera/layer controls                             | Shared provider state/commands and existing controlled visibility; source updates preserve the camera                                                 |
| Plot inside caller-owned card with external controls/data  | `ChartSurface`, `ChartProvider`, `ChartHeading`, `ChartZoomControls`, `ChartDataView`; ExternalComposition story                                      |
| Larger typography, long labels and narrow/short containers | Shared typography roles, actual measured map/native geometry, map control exclusions and selection in normal document flow; browser + View Rule gates |
| Nongeographic/native consumers stay lightweight            | Native plots share only internal SVG/measurement helpers; CJS/ESM/SSR and bundle isolation checks                                                     |
| Existing recipes retain useful behavior                    | All original component suites, guide integration tests, three-browser chart/map audits and existing layout contract                                   |

Typography roles are CSS-pixel title/description/label/control/legend/detail values. Defaults are 18/14/12/14/12/12, with explicit engine options taking precedence. Native components expose relevant roles; textless Sparkline marks instead retain screen-space dimensions. Font changes must propagate through DOM/engine styles and measurement. The 12px annotation / 14px prose floor is the declared example-review contract, not a general accessibility certification.

## Performance evidence

A focused 1,000-row, six-column grouped-grid profile with ten collapsed groups recorded 6,000 expensive cell-renderer calls before the change and zero afterward. An illustrative single local sample decreased from 185ms to 91ms; this is not a general benchmark or performance guarantee. Selection/select-all tests include hidden selectable rows and exclude disabled rows. The map test uses 500 facilities and five selection/visibility updates, requires zero unchanged-source uploads, then requires the changed source to update when the data changes.

## Required final verification

Run the complete package tests, TypeScript, build/declarations, lint, Storybook, CJS/ESM imports/SSR and preview bundle isolation checks. Run `scripts/check-style-package.mjs` after the build: both ordinary workspace tarballs and release-directory tarballs must install into isolated consumers, resolve public component/utility/CSS/Sass entries, render on the server, and compile the complete Sass dependency set into production CSS. Workspace-relative imports alone do not establish package adoption readiness.

Run Chrome/Firefox/Safari chart and map audits and the chart/map View Rule workflows. Inspect actual artifacts for mobile, long labels, larger text, short viewports, dateline geography and separate companions. Preserve exact source/run provenance in the PR. Hosted documentation must include the composed and native acceptance fixtures, and hosted-map verification must pass. Remaining incomplete automated accessibility checks require honest reporting rather than a blanket compliance claim.
