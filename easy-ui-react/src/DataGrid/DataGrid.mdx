# DataGrid

A `DataGrid` is an interactive table used for working with a large collection of data in a scannable way.

<Canvas of={DataGridStories.Default} />

## `DataGrid` architecture

`DataGrid` is a single component that takes in a `columns` array to define its structure and a `rows` array to define its content. `columns` and `rows` must have `key`s. `rows` must have a corresponding property for each `key` in `column`.

`DataGrid` uses [render props](https://react.dev/reference/react/cloneElement#passing-data-with-a-render-prop) to control the rendering of its column cells, row cells, and expanded row content. Use `renderColumnCell`, `renderRowCell`, and `renderExpandedRow` respectively.

Additional props exist to enable different functionality for the table, such as sorting and selection. See the snippet below for a quick-start guide on using the component.

```tsx
const columns = [
  { key: "name", name: "Name" },
  { key: "email", name: "Email" },
];

const rows = [
  {
    key: 1,
    name: "Julie Smith",
    email: "julie.smith@example.com",
  },
  {
    key: 2,
    name: "Sam Frost",
    email: "sam.frost@example.com",
  },
];

<DataGrid
  aria-label="Example data grid"
  columns={columns}
  rows={rows}
  renderColumnCell={(column) => <span>{String(column.name)}</span>}
  renderRowCell={(item, columnKey, row) => <span>{String(item)}</span>}
  renderEmptyState={() => <span>No Data</span>}
  // Handler that is called when a user performs an action on the cell
  onCellAction={(key) => {}}
  // Handler that is called when a user performs an action on the row
  onRowAction={(key: Key) => {}}
  // Enable row expansion
  renderExpandedRow={(rowKey: Key) => <div>Expanded row content</div>}
  defaultExpandedKey={1}
  expandedKey={1}
  onExpandedChange={(key) => {}}
  // Customize how many rows show before scroll, or use "auto" to fit the
  // height the container makes available
  maxRows={7}
  // Enable selection. Can be "multiple" or "single"
  selectionMode="multiple"
  defaultSelectedKeys={[]}
  selectedKeys={[]}
  onSelectionChange={(keys) => {}}
  // Support a kebab menu on each row
  rowActions={(rowKey) => [
    {
      type: "menu",
      renderMenuOverlay: () => (
        <Menu.Overlay onAction={action("Menu item clicked!")}>
          <Menu.Item>Action 1</Menu.Item>
          <Menu.Item>Action 2</Menu.Item>
        </Menu.Overlay>
      ),
    },
  ]}
  // Support alternate header color
  headerVariant="secondary"
  // Enable sorting
  sortDescriptor={{ column, direction }}
  onSortChange={({ column, direction }) => {
    // update row order
  }}
  columnKeysAllowingSort={["name"]}
  // "sm", "md" (default), or "lg"
  size="lg"
  isLoading={false}
/>;
```

## With Selection

`DataGrid` supports selection with the `selectionMode` prop. Pass in `multiple` to allow selecting multiple rows. Pass in `single` to allow selecting a single row at a time.

Selection can be controlled with the `selectedKeys` and `onSelectionChange` props. Use `defaultSelectedKeys` to control only the initial selection.

```tsx
<DataGrid
  {/** other data grid props */}
  selectionMode="multiple"
  defaultSelectedKeys={[/** row keys */]}
  selectedKeys={[/** row keys */]}
  onSelectionChange={(keys: "all" | Key[]) => {
    /** Run code when selection changes */
  }}
/>
```

## With Row Expansion

`DataGrid` supports row expansion through the `renderExpandedRow` prop. Supplying a function to this render prop, with the content to render for each row, will show expansion buttons on each row for the user to expand.

Expansion can be controlled with the `expandedKey` and `onExpandedChange` props. Pass `null` to keep every detail closed; omitting `expandedKey` selects uncontrolled behavior. `onExpandedChange` receives the next state: the row key when opening or switching rows, and `null` when closing the open row. A controlled grid waits for the prop to change. Use `defaultExpandedKey` to control only the initial row to expand.

While `isLoading` is true, the grid hides expanded details and suspends their layout measurements without changing the expanded key or calling `onExpandedChange`. When loading finishes, details return if that row is present. A controlled key updated during loading is honored when the data rows return.

```tsx
<DataGrid
  {/** other data grid props */}
  renderExpandedRow={(rowKey: Key) => (
    <div>Expanded row content for {rowKey}</div>
  )}
  defaultExpandedKey={/** initial key of expanded row (uncontrolled) */}
  expandedKey={/** key of expanded row (controlled) */}
  onExpandedChange={(key: Key | null) => {
    /** Store the next expanded key, including null when closing */
  }}
/>
```

## With Kebab Menu

`DataGrid` supports rendering a kebab menu on each row through the `rowActions` prop.

Provide an array of actions to the `rowActions` prop with an action type of `menu` and a `<Menu.Overlay />` through the `renderMenuOverlay` function.

```tsx
<DataGrid
  {/** other data grid props */}
  rowActions={(rowKey: Key) => [
    {
      type: "menu",
      renderMenuOverlay: () => (
        <Menu.Overlay onAction={action("Menu item clicked!")}>
          <Menu.Item>Action 1</Menu.Item>
```

## With Sort

`DataGrid` supports sorting through the `sortDescriptor` and `onSortChange` props.

`sortDescriptor` accepts an object with a `column` key and a `direction` of `ascending` or `descending`. `onSortChange` accepts a function with a sort descriptor for updating the data grid rows sort.

Consumers can utilize React Stately's [`useAsyncList`](https://react-spectrum.adobe.com/react-stately/useAsyncList.html) hooks to manage data loading and sorting. See its [documentation](https://react-spectrum.adobe.com/react-stately/useAsyncList.html) for more use cases, such as server-side sorting.

```tsx
function SortableDataGrid(args: DataGridProps) {
  const list = useAsyncList({
    async load() {
      return await Promise.resolve({
        items: [
          /** Rows */
        ],
      });
    },
    async sort({ items, sortDescriptor }) {
      return {
        items: items.sort((a, b) => {
          const comparison = /** Comparison logic */;
          return comparison;
        }),
      };
    },
  });
  return (
    <DataGrid
      columns={[/** Column definitions */]}
      rows={list.items}
      sortDescriptor={list.sortDescriptor}
      onSortChange={list.sort}
      columnKeysAllowingSort={[/** List of sortable columns */]}
    />
  );
}
```

## With Grouping and Subtotals

Pass `grouping` to gather rows by a string or numeric key and append a subtotal after each group. Rows need not be adjacent. Groups appear in the order their keys first occur in `rows`; data rows retain their relative order within each group. Numeric and string keys are distinct (`1` and `"1"` form different groups).

```tsx
<DataGrid
  aria-label="Service Split"
  columns={columns}
  rows={rows}
  renderColumnCell={(column) => column.name}
  renderRowCell={(cell) => String(cell ?? "")}
  grouping={{
    getGroupKey: (row) => row.carrier,
    aggregators: {
      packages: (groupRows) =>
        groupRows.reduce((sum, row) => sum + row.packages, 0),
      spend: (groupRows) => groupRows.reduce((sum, row) => sum + row.spend, 0),
    },
    renderSubtotalCell: (cell, columnKey, group) => {
      if (columnKey === "carrier") return `${group.key} subtotal`;
      return String(cell ?? "");
    },
  }}
/>
```

The optional `grouping` prop has type `DataGridGrouping<C, R>`, exported from `@easypost/easy-ui/DataGrid/types`:

| Property             | Type                                                                             | Behavior                                                                                                                                                                                                            |
| -------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getGroupKey`        | `(row: R) => Key`                                                                | Required. Returns the group key from each original data row.                                                                                                                                                        |
| `getGroupLabel`      | `(group: DataGridGroup<R>) => string`                                            | Optional. Human-readable name for the default subtotal and group disclosure's accessible name. Defaults to `String(group.key)`; does not change identity or collapse keys.                                          |
| `aggregators`        | `Partial<Record<ColumnKey<C>, (rows: readonly R[]) => unknown>>`                 | Required. Each configured column receives all data rows in its group and returns its subtotal value. Reducers can compute sums, counts, averages, or other summaries. An empty object creates label-only subtotals. |
| `renderSubtotalCell` | `(cell: unknown, columnKey: ColumnKey<C>, group: DataGridGroup<R>) => ReactNode` | Optional. Formats subtotal values independently of `renderRowCell`. `group` contains the original group `key` and read-only `rows`.                                                                                 |

By default, the first column displays `"{group label} subtotal"`; an aggregator for that column overrides the label. Other columns display their aggregated values converted to strings, or remain blank if no aggregator is configured. `null` and `undefined` render blank. Custom subtotal renderers receive these same values, including the default label. `getGroupLabel` remains the disclosure name even when a custom renderer replaces the visible subtotal. Use it for opaque database IDs or translated group names. Keep monetary values in integer minor units (for example, cents), sum them, and format them as currency in the renderers.

Subtotal rows use semibold text, a neutral background tint, and a top separator, retain the normal row and cell roles, and expose `data-ezui-data-grid-subtotal="true"` for structural identification. Synthetic row keys are internal; `renderRowCell`, `rowActions`, and expansion callbacks continue to receive only data rows or their keys. Subtotals remain reachable with arrow keys so keyboard users can read their values. They have no selection checkbox, detail-expansion button, or row actions, and do not trigger `onRowAction` or `onCellAction`. Optional group disclosure buttons are described below.

Subtotal content retains its React identity by group key and column key when groups reorder or consumer row keys collide with internal subtotal keys. Stateful controls in a subtotal keep their values and focus while that group and column remain present.

Sorting remains controlled by `sortDescriptor` and `onSortChange`: sort the source `rows`, and the grid regroups them and recomputes subtotals. Subtotals stay after their group, outside the sorted data. Selection, including select-all, applies only to selectable data rows and respects `disabledKeys`. The existing `"all"` selection callback value retains its meaning. The existing restriction against combining selection and expansion still applies.

Subtotals use only the supplied `rows`, so filtering or pagination produces subtotals for the visible subset, not the full server dataset. An empty array produces the existing empty state. `maxRows` counts all rendered body rows, including subtotals. Omit `grouping` to keep existing flat-grid behavior.

The Service Split example reproduces the Analytics homepage's carrier and service-level breakdown using representative data. It totals package counts and spend for each carrier.

### Collapsible groups

Set `grouping.isCollapsible` to show a chevron button beside each subtotal label. Groups start expanded. Clicking the chevron, or pressing Enter or Space while it is focused, hides the group's detail rows and keeps its subtotal visible. The button announces the group name and expanded state. Subtotals keep their position after their group when expanded.

| Grouping option        | Type                       | Behavior                                               |
| ---------------------- | -------------------------- | ------------------------------------------------------ |
| `isCollapsible`        | `boolean`                  | Enables disclosure buttons. Defaults to `false`.       |
| `defaultCollapsedKeys` | `Iterable<Key>`            | Initially collapsed group keys in uncontrolled mode.   |
| `collapsedKeys`        | `Iterable<Key>`            | Controlled set of collapsed group keys.                |
| `onCollapsedChange`    | `(keys: Set<Key>) => void` | Receives the next collapsed group keys after a toggle. |

These are **group keys**, returned by `getGroupKey`, rather than row keys or internal subtotal keys. Numeric and string keys remain distinct. The three state options require `isCollapsible: true`.

```tsx
const [collapsedKeys, setCollapsedKeys] = useState<Set<Key>>(new Set());

<DataGrid
  {...tableProps}
  grouping={{
    getGroupKey: (row) => row.carrier,
    aggregators: {
      packages: (rows) => rows.reduce((total, row) => total + row.packages, 0),
      spend: (rows) => rows.reduce((total, row) => total + row.spend, 0),
    },
    isCollapsible: true,
    collapsedKeys,
    onCollapsedChange: setCollapsedKeys,
  }}
/>;
```

Omit `collapsedKeys` to let the grid manage state. Use `defaultCollapsedKeys` to start selected groups closed. A controlled consumer updates `collapsedKeys` in response to `onCollapsedChange`; supplying the prop without a handler makes it read-only.

Collapsing changes visibility only. Aggregators still receive every supplied row in the group, selected rows remain selected, and select-all includes selectable details in collapsed groups. Hidden rows do not call `renderRowCell` or `rowActions`; the complete collection remains available for selection. No selection or detail-expansion callback fires merely because a group is collapsed. Open detail content is temporarily hidden and restored when its group reopens. Sorting and new data preserve collapse state by group key. Arrow navigation skips hidden rows; focus stays on the toggle, or moves to the subtotal if a controlled update hides the focused detail row. If focus was inside expanded detail content, it returns to that group's disclosure button. Focus elsewhere stays where it is. `maxRows` counts visible body rows, including the retained subtotals.

## Height and Column Layout

The grid fills its container's width. Scrollbars appear only when content exceeds the available width or an explicit height limit; they do not need a visibility prop.

| Control         | Type                                                   | Behavior                                                                                                                                                     |
| --------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `maxRows`       | `number` or `"all"`                                    | Limit height by body-row count, including subtotals, or use `"all"` for natural content height. The existing default of `999` is unchanged.                  |
| `maxHeight`     | `CSSProperties["maxHeight"]`                           | Optional height limit such as `320` (pixels), `"60vh"`, or `"calc(100vh - 16rem)"`. Takes precedence over `maxRows`. Short tables keep their natural height. |
| `columnOptions` | `Partial<Record<ColumnKey<C>, DataGridColumnOptions>>` | Per-column layout, applied consistently to the header, data cells, and subtotal cells.                                                                       |
| `size`          | `"sm"`, `"md"`, or `"lg"`                              | Existing row-density control. Defaults to `"md"`.                                                                                                            |

`DataGridColumnOptions` is exported from `@easypost/easy-ui/DataGrid/types`:

| Column option | Type                              | Behavior                                                                                                                                                    |
| ------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `alignment`   | `"start"`, `"center"`, or `"end"` | Sets horizontal alignment. Explicit alignment overrides the numeric default.                                                                                |
| `isNumeric`   | `boolean`                         | Uses equal-width digits and defaults to end alignment. Formatting currency, percentages, and locale-specific numbers remains the renderer's responsibility. |
| `width`       | `CSSProperties["width"]`          | Preferred column width. Accepts pixels as numbers or CSS lengths such as `"20%"`. Automatic table layout may widen a column to fit its content.             |
| `minWidth`    | `CSSProperties["minWidth"]`       | Keeps columns readable when space is limited. If the column minimums exceed the container width, the table scrolls horizontally.                            |

Keep presentation in `columnOptions`, keyed by the same keys as `columns`, so existing arbitrary column metadata retains its meaning. Selection, expansion, and action columns are added independently; they do not shift which data columns receive these options.

```tsx
<DataGrid
  {/** other data grid props */}
  maxRows="all"
  columnOptions={{
    carrier: { width: "20%", minWidth: 184 },
    service: { width: "40%", minWidth: 200 },
    packages: { width: "20%", minWidth: 140, isNumeric: true },
    spend: { width: "20%", minWidth: 144, isNumeric: true },
  }}
/>
```

Use natural height for a short table on a page. Add `maxHeight={280}` when the surrounding dashboard panel intentionally needs a scrollable table. The Service Split story exposes these options in Storybook Controls. Enter CSS units in the text-based `maxHeight` control (for example, `280px`); in application code, both `280` and `"280px"` are supported.

## With Custom Rendering

`DataGrid` supports custom rendering of content for row and column cells using the `renderRowCell` and `renderColumnCell` props.

In the example below, to make the status text green or red depending on whether a user's active or inactive, target that column and adjust the style accordingly.

```tsx
<DataGrid
  {/** other data grid props */}
  renderRowCell={(cell, columnKey) => {
    if (columnKey === "status") {
      return (
        <span
          style={{
            whiteSpace: "nowrap",
            color: cell === "Inactive" ? "red" : "green",
          }}
        >
          {String(cell)}
        </span>
      );
    }
    return <span style={{ whiteSpace: "nowrap" }}>{String(cell)}</span>;
  }}
/>
```

## Footer

`DataGrid` supports rendering a footer through the `renderFooter` prop. The footer is a bar at the foot of the grid's frame, outside the region that scrolls, so the rows scroll above it and it casts a shadow over them once there's anything below the fold. `maxRows` still counts body rows with a footer present. It stays mounted through the empty and loading states.

`renderFooter` controls what goes inside. `<DataGrid.Footer />` lays that content out into `start`, `center`, and `end` regions, which are positional rather than named after what they hold — the footer carries no assumptions about how a consumer pages through the grid.

`<DataGrid.Pagination />` and `<DataGrid.RowsPerPage />` cover the common case. Both are fully controlled.

```tsx
const [page, setPage] = useState(1);
const [rowsPerPage, setRowsPerPage] = useState(50);

<DataGrid
  aria-label="Data grid with a footer"
  columns={columns}
  rows={rows}
  renderColumnCell={(column) => <span>{String(column.name)}</span>}
  renderRowCell={(item) => <span>{String(item)}</span>}
  renderFooter={() => (
    <DataGrid.Footer
      center={<DataGrid.Pagination page={page} count={10} onChange={setPage} />}
      end={
        <DataGrid.RowsPerPage
          rowsPerPage={rowsPerPage}
          options={[25, 50, 100]}
          onChange={setRowsPerPage}
        />
      }
    />
  )}
/>;
```

## Auto Height

`maxRows` takes `auto` in place of a row count, which bounds the data grid by the height its container makes available and scrolls the rows within it. This suits a data grid in a fluid layout, where the room it has to work with comes from the page rather than from a number settled on in advance.

The dashed outline in the stories below marks the container's space, so it's visible what the data grid is sizing itself against.

<Canvas of={DataGridStories.AutoHeight} />

<Controls of={DataGridStories.AutoHeight} />

An auto height data grid shrinks to its rows when they don't fill the space it's offered, so it never draws an empty region beneath the last row.

<Canvas of={DataGridStories.AutoHeightWithFewRows} />

Some ancestor has to establish a height for `auto` to have space to work from. It needn't be the data grid's parent; a height set once at the top of a layout carries down through flex and grid tracks.

```tsx
// The height is established once, and the levels beneath it pass it down
<div style={{ height: "100dvh", display: "flex", flexDirection: "column" }}>
  <PageHeader />
  <div
    style={{
      display: "flex",
      flexDirection: "column",
      flex: "1 1 auto",
      minHeight: 0,
    }}
  >
    <DataGrid maxRows="auto" {...props} />
  </div>
</div>
```

Two things to watch for in the surrounding layout:

- Flex and grid items between that height and the data grid need `min-height: 0`. They floor at their content height otherwise, which lets the data grid run past the bottom of the layout instead of scrolling inside it.
- A plain block container holding a sibling above the data grid measures `auto` against the container's whole height rather than the room left over, which overflows it. Laying that container out as a flex column or a grid resolves it.

With no height established anywhere above it, `auto` has nothing to bound the data grid by, and it falls back to drawing every row.

### Filling a Container

A container that stretches the data grid rather than letting it shrink turns the auto height into a fill. The rows take the extra room and the footer holds the bottom of the layout however few rows there are, which is what a data grid anchored to the foot of a page wants.

<Canvas of={DataGridStories.AutoHeightFillingItsContainer} />

```tsx
// A single track stretches the data grid to the full height of the container
<div style={{ height: "100dvh", display: "grid", gridTemplateRows: "1fr" }}>
  <DataGrid maxRows="auto" {...props} />
</div>
```

### Scrolling Both Axes

Content wider than the frame scrolls horizontally within the same bound. The rows scroll under the column headers and past the sticky selection column, while the footer holds the bottom of the frame and keeps its own width rather than stretching to the width of the table.

### Long labels in a narrow container

The following example uses a 480-pixel panel that also fits smaller screens. Its long service names use the existing `Text whiteSpace="nowrap"` renderer so content stays within the grid's fixed row heights. Horizontal scrolling exposes the full text and numeric columns, while the carrier column stays visible. This is genuine content overflow; natural height avoids an additional vertical scrollbar.

```tsx
<div style={{ width: 480, maxWidth: "100%" }}>
  <DataGrid
    {...tableProps}
    maxRows="all"
    columnOptions={{
      carrier: { width: 212, minWidth: 212 },
      service: { minWidth: 320 },
      packages: { minWidth: 140, isNumeric: true },
      spend: { minWidth: 144, isNumeric: true },
    }}
    renderRowCell={(cell) => <Text whiteSpace="nowrap">{String(cell)}</Text>}
  />
</div>
```

Use concise display labels in the frozen first column so it leaves room for the other columns on small screens. Column widths are preferred widths under automatic table layout; they do not truncate content. This example retains full labels without adding a wrapping or truncation API.
