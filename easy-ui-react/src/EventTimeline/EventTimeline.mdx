# EventTimeline

A reusable selectable chronology. The caller owns ordering, interpretation, identifiers, and whether events belong to the same path. The timeline does not deduplicate events or infer physical histories.

## Event identity and independent metrics

The event's time, label, facility type, and location form its identity. Minimal measurements sit beside that identity in the same event row; compact and expanded measurements sit beneath it. Every pill contains both the metric label and its current value. The event-selection dot is independent of metric health: an arrival can have a healthy dwell time and an elevated exception rate at the same time.

The timeline frequently occupies **360–480px beside a map**. Facility text can wrap rather than being truncated to make room for statistics. The selected status dot retains clearance from the event text. Pills consistently display “Dwell time 6 h” and “Exception rate 2% · Elevated”, with no repeated label outside the pill.

The three presentations below use identical synthetic observations at a **420px timeline width**:

- **Minimal:** compact event identity, facility icon, and both labeled metric pills in the same event row. Pills wrap within their trailing slot when needed; the group stays beside the event. No distributions.
- **Compact:** visible facility type and location, followed by one row per metric. Each pill contains its label and current value, with a concentration reference alongside when it fits.
- **Expanded:** the same event identity and labeled metric pills, with a larger distribution beneath each headline. The current value is not repeated in a second summary.

The reference shows one indicator for the current value. Percentile dots and tiny percentile labels are omitted. Distribution intensity describes the supplied reference, and only the policy interval containing the current value receives an assessment color. Other ranges remain visible in neutral color. Both the dwell-time and exception-rate examples have their own reference and assessment.

The example data is synthetic. The dwell reference contains completed durations; the exception reference contains percentage rates from comparable facility windows. Neither the component nor the example derives a percentage distribution from binary outcomes or treats a percentile as a health threshold.

## Compose metrics

```tsx
import { EventTimeline } from "@easypost/easy-ui/EventTimeline";
import { EventMetrics } from "@easypost/easy-ui/EventMetrics";

<EventTimeline
  events={events}
  selectedId={selectedId}
  onSelectedIdChange={setSelectedId}
  renderMetrics={(event) => (
    <EventMetrics
      variant="compact"
      metrics={metricsByEvent[event.id] ?? []}
      ariaLabel="Facility observations"
    />
  )}
/>;
```

For **minimal**, use `size="compact"` and pass the same renderer through `renderTrailing` with `<EventMetrics variant="minimal" />`. This keeps both pills in the event row, outside its selection button.

`renderMetrics` is available on every event, including the final observation. It places caller-owned content beneath the event identity and outside the event-selection button. `EventMetrics` accepts already formatted values and references, so durations, percentages, counts, and other measurements can share this composition without a domain dictionary in the timeline.

`locationIcon` accepts a caller-supplied icon. Compact event size keeps the icon and location while retaining the facility type for assistive technology; default and detailed sizes also display the facility type. Keep the metric presentation independent of the event's size.

## Selection and context

Supply `selectedId` and `onSelectedIdChange` to coordinate selection with an external map or details panel. A separate `onLocationSelect` callback exposes the location and event IDs; map pan and zoom remain application-owned.

Supply `relatedIds` to highlight events within a selected location, connection, or candidate path while keeping the complete timeline available. Selection and context highlighting are independent. An event's optional `detailLabel` adds concise caller-supplied context, such as a receipt time that distinguishes otherwise identical observations. It appears below the location in default and detailed rows; compact rows expose it as an accessible description.

Event time and received time are different fields; no implicit ordering or timestamp repair occurs. `renderTrailing` places minimal metric pills or other caller-owned summaries beside event identity, while `renderMetrics` places compact or expanded measurements below it. `renderDetails` supplies other content associated with an event. `renderInterval` supplies content associated with the interval following an event and is not rendered after the final event.

Keyboard navigation supports Up/Down and Home/End while retaining native button activation by Enter and Space.
