# InvestigationWorkspace

An organism composing `EventTimeline`, `NetworkMap`, and a persistent detail panel. One controlled selection links observations, locations, candidate histories, and shared connections. Applications supply the records and their relationships; the component never chooses a true history or infers parcel identity.

## Controlled selection

```tsx
import {
  InvestigationWorkspace,
  type InvestigationSelection,
} from "@easypost/easy-ui/InvestigationWorkspace";

const [selection, setSelection] = useState<InvestigationSelection>(null);

<InvestigationWorkspace
  events={events}
  locations={locations}
  segments={segments}
  paths={candidatePaths}
  map={{ mapStyle, workerUrl }}
  selection={selection}
  onSelectionChange={setSelection}
  renderDetails={({ event, location, paths }) => (
    <ApplicationDetails event={event} location={location} paths={paths} />
  )}
/>;
```

Selection is `null`, `{type: "event", eventId}`, `{type: "location", locationId}`, `{type: "path", pathId}`, or `{type: "segment", segmentId}`. Location, path, and segment selections may include `eventId` for scoped stepping. Selecting a member event retains that scope; selecting an unrelated event switches to event selection. Callbacks request a change; only the caller updates the controlled value.

Events use the timeline's stable IDs, `locationId`, and optional `pathIds`. Candidate paths have stable `id`, `label`, optional `description`, and `segmentIds` referencing supplied map connections. No timestamps are sorted and no duplicate descriptions are collapsed. A path choice highlights supplied connections without removing other events. Event selection highlights its location and all supplied candidate memberships. Shared-connection selection exposes all associated paths and their events, without asserting those events occurred on that connection.

Hovering the map previews its existing inspection card without changing the persistent panel. Click, tap, Enter, and Space select. Timeline arrow keys, Home/End, and previous/next controls select events. The map's markers and the “Browse locations and connections” disclosure provide keyboard selection and remain usable if the engine fails. Unknown or invalid coordinates are left to the map's existing validation; unlocated events remain selectable. Removed selected records show an unavailable state instead of silently choosing another observation.

## Composition and layout

`map` accepts the existing `NetworkMap` options except its location/segment selection and data, which the workspace coordinates. Basemap, worker, camera policy, additional overlays, inspection renderers, legend, and exact data remain available. Selection does not automatically move the camera. The workspace omits duplicate map selection details, legend, and full raw-data tables by default. Individual location inspection is required, so clustered markers are not exposed by this composition.

`timeline` accepts the existing size and content slots. `renderDetails(context)` adds caller-owned content below the selection summary; health assessments, distributions, facility summaries, and application actions are optional. Its context contains the selected event/location/path/segment, scoped events, all associated paths, and availability. Event time and received time remain separate.

On wide containers, events sit beside the map with details immediately below it. Below 740px, the same mounted views stack map → details → events; selection and chart state survive resizing. `labels` customizes section headings, candidate-path label, navigation and empty prompt; `ariaLabel` names the workspace.
