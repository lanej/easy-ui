# MetricCard

Show a formatted metric with a secondary unit and an optional comparison. Applications own aggregation, units, reporting periods, calculations, and business meaning.

```tsx
import {
  MetricCard,
  MetricContent,
  MetricComparisonContent,
  MetricGroup,
} from "@easypost/easy-ui/MetricCard";
```

## Summary and row are different compositions

The default `layout="summary"` always places the label above the value and its comparison, aligned to the start edge. Extra width does not move the number away from its label. The pill stays centered beside the reading; oversized content wraps without clipping. `MetricCard` adds a frame; `MetricContent` does not.

`layout="row"` is a label/value/change row. Use direct `MetricContent` children inside `MetricGroup layout="row"` to align numeric endpoints and comparison starts across the entire list. These are shared CSS grid columns, not manually sized pills or floating values. Long labels and values can wrap within their columns. The group does not add a heading, card, or landmark.

## One section, not a card around every number

Use one caller-owned Card with `MetricGroup` and unframed metrics. The summary group adapts its column count to its actual container width. Every metric retains the same label-above-reading composition on mobile and desktop.

Reporting and comparison periods belong in the group header. Currency belongs to the cost metric, not to the shared context for counts, percentages, and durations. Keep metric-specific qualifications visible.

## Hierarchy and typography

`size` is independent of layout and framing. `sm` uses a 20px value, `md` 24px, and `lg` 28px. Labels remain 14–15px; units and comparisons use 13–14px text. `MetricGroup` supplies the size and layout defaults for its children; individual metrics can override them.

Use `unit="days"` with `value="2.4"` to keep the suffix secondary and on the number's baseline. Values can also remain fully formatted strings such as `"97.8%"`. The component never parses a value to discover its units. Both the unit and comparison are suppressed for missing or loading values.

Custom `valueSize` and `typography` remain available. Invalid `valueSize` falls back to the selected preset. The passive comparison uses a compact tinted `Pill`; interactive pills retain their existing sizes.

## Direction is not sentiment

Supply `direction` with an unsigned, formatted comparison magnitude to show a compact arrow, for example `label: "4.2%", direction: "decrease"`. Increase and decrease use up and down arrows; unchanged uses an equals sign. Direction stays visible without color. `accessibilityLabel` can supply a localized description of the complete change.

`sentiment` is independent: lower cost may be positive, a higher exception rate negative, and increased volume neutral. No sign or sentiment is inferred from the value string. Omitting `direction` preserves a complete text label such as `"4.2% lower"`.

A change from 96.6% to 97.8% is **1.2 percentage points**, not 1.2 percent. Applications calculate and format comparisons. Pill owns its muted text/background pair in both themes; metric text must not override it.

## Shared context without repetition

Comparisons require exactly one of `baseline` (displayed locally) or `baselineId` (referencing a visible baseline in the same document with `aria-describedby`). Use a unique ID, such as React's `useId()`, and keep the referenced text mounted and visible. Independently embedded metrics need their own local baseline.

```tsx
const baselineId = useId();

<Card as="section" aria-label="Shipping overview" padding="2">
  <p id={baselineId}>June 1–30 · vs previous 30 days</p>
  <MetricGroup>
    <MetricContent
      label="Average rated cost"
      value="$5.20"
      unit="USD"
      comparison={{
        label: "4.2%",
        direction: "decrease",
        sentiment: "positive",
        baselineId,
      }}
    />
    <MetricContent label="Labels purchased" value="24,810" />
  </MetricGroup>
</Card>;
```

When a comparison describes a value, supply `comparison` to keep them grouped. Use `MetricComparisonContent` independently only when the comparison itself is the content.

## Loading, unavailable, and composed values

Use `isLoading` to suppress stale readings. Use `null` for unavailable data; an observed zero remains `"0"`. Loading and empty labels can be localized. For a failed query, compose a Banner and retry action rather than presenting zero. React-element values can contain SignedValue atoms without losing the surrounding metric's hierarchy.

## Migration

`KpiTile` was a duplicate wrapper and remains removed. Use MetricCard for standalone framing or MetricContent inside an existing section. Map metric label/value to `label`/`value`; provide an explicit comparison baseline. Do not restore the decorative icon chip or Point-in-time pill.

The earlier draft's `compact`/`stacked` layout names are replaced by `row`/`summary`. Typography is now a separate `size` choice; a summary does not imply larger text or extra padding.

For trends, compose a Chart in the caller-owned layout with labelled axes, an explicit domain, and exact observations in its data disclosure. MetricCard does not accept a trend prop.
