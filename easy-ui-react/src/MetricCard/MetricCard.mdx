# MetricCard

Show a metric and its comparison baseline. Compose `Chart` alongside metric content when a trend is needed. Values and comparisons are formatted by the application, which owns the metric definition, locale, time zone, and aggregation.

<Canvas of={MetricCardStories.ShippingOverview} />

## Comparison meaning

Specify the comparison period and units. A change from 96.6% to 97.8% is **1.2 percentage points**, not 1.2 percent. Direction does not determine sentiment: decreasing cost can be positive, while increasing volume can be neutral. Only set sentiment when the application can justify that interpretation. Use text that makes the direction clear without color.

Positive comparisons use dark text on the success background to preserve text contrast. Give cards distinct labels when multiple metrics or states appear together so their accessible regions can be distinguished.

## Reusing content

`MetricContent` exposes the same value, comparison, loading and missing-data behavior without a Card or region wrapper. Place it in a caller-owned Card, section, or report layout. `MetricComparisonContent` is independently usable when a comparison and its explicit baseline belong elsewhere. Both are available from the MetricCard entry.

`MetricCard` retains its existing framed recipe. `typography` configures text-role sizes in CSS pixels; `valueSize` controls the emphasized value separately (28 by default). Comparison sentiment remains explicit and neutral by default in every composition.

<Canvas of={MetricCardStories.CallerOwnedFrame} />

Values also accept a React element, allowing `SignedValue` atoms or separately colored range endpoints to compose into the same metric molecule. Sign colors remain opt-in; metric content does not infer business sentiment from a formatted string. Smaller `valueSize` settings scale the value row without retaining a card-sized empty height.

<Canvas of={MetricCardStories.SignedValues} />

## Loading and unavailable values

Pass `isLoading` while a query is loading. The previous value and comparison are suppressed. Pass `null` for an unavailable value and a formatted `"0"` for an observed zero. For query failures, compose an existing `Banner` with a retry action; do not present a failed query as zero or an empty successful result. Loading and empty labels can be localized.

## Trends

Use the Apache ECharts-backed `Chart` component for trends, with labelled axes, an explicit domain, and exact observations in its data disclosure. `MetricCard` and `MetricContent` no longer accept a `trend` prop; place a `Chart` in a caller-owned layout instead.
