# WaffleChart

One cell per supplied item, with compact linked summaries, grouped pools, and accessible inspection. Native HTML/CSS; no chart engine. Import from `@easypost/easy-ui/WaffleChart`.

Applications supply the items, category mappings, group membership, relationships, and the meaning of the data. Counts are exact: 7 items produce 7 cells, and 137 items produce 137 cells. The chart does not normalize to 100 cells, calculate percentages, or infer allocation or available capacity.

## Usage

The smallest useful input is an accessible name, one item, and its category:

```tsx
import { WaffleChart } from "@easypost/easy-ui/WaffleChart";

<WaffleChart
  accessibilityLabel="Example resource pool"
  items={[{ id: "resource-1", label: "Resource 1", categoryId: "design" }]}
  categories={[{ id: "design", label: "Design", color: "primary.500" }]}
/>;
```

Use stable, unique item IDs across reordering and updates. Category and group IDs must also be unique within their collections. Labels are caller-supplied exact text; `metadata` carries caller-owned details without changing the item's identity or count. Category colors are explicit Easy UI theme-token aliases, independent of category array order.

## Props

<ArgTypes of={WaffleChart} />

The public entry also exports `WaffleChartProps`, `WaffleChartItem`, `WaffleChartItemOrder`, `WaffleChartCategory`, `WaffleChartGroup`, `WaffleChartSelection`, `WaffleChartHighlight`, `WaffleChartInspection`, and `WaffleChartGroupAnchor`. Item, props, and inspection types accept a metadata type parameter.

- `variant="default"` supports grouped captions, a legend, and inspection. `variant="compact"` is always passive and omits captions, legend, details, and controls. `interaction="none"` makes the default presentation passive too.
- `itemOrder` is `"input"` (the default) or `"category"`. Input order preserves the supplied item order within each displayed group. Category order clusters cells by category ID in the supplied `categories` order, preserving input order within each category. Unknown category IDs follow known categories in first-seen ID order. Categories with the same color remain separate clusters.
- `maxColumns` is an upper column limit, not a fixed width. `cellSize` and `gap` are CSS pixels. Defaults are 12 columns, 20px cells, and 6px gaps; compact defaults to 8px cells and 3px gaps. Interactive cells retain at least a 24px pointer target, independently of the visual cell size.
- `showCount` and `showLegend` default to `true`. `countLabel(count)` formats the exact total for the default presentation and accessible compact summary; the compact adjacent count remains numeric. `emptyMessage` defaults to "No items supplied"; `ungroupedLabel` defaults to "Other items".

## Examples

### Passive summary inside a link

```tsx
<a href="/priorities/example">
  Example priority
  <WaffleChart
    variant="compact"
    accessibilityLabel="Priority resources"
    items={[
      { id: "designer-1", label: "Designer 1", categoryId: "design" },
      {
        id: "engineer-1",
        label: "Engineer 1",
        categoryId: "engineering",
        draft: true,
      },
    ]}
    categories={[
      { id: "design", label: "Design", color: "primary.500" },
      { id: "engineering", label: "Engineering", color: "neutral.600" },
    ]}
  />
</a>
```

The entire row remains one link. Compact cells create no nested buttons or focus stops, even if inspection callbacks are supplied. The adjacent exact count and `/ Draft` count stay visible, while the accessible summary includes every item label, category, and supplied draft or muted state. Draft cells also have a patterned slash marker, so draft status does not depend on color. A supplied selection is announced as a selected item or selected group in the compact summary. Full-sized passive cells announce selected state too; interactive control names stay stable and use `aria-pressed`.

### Group membership and shared relationships

```tsx
import type {
  WaffleChartCategory,
  WaffleChartGroup,
  WaffleChartItem,
} from "@easypost/easy-ui/WaffleChart";

const categories: WaffleChartCategory[] = [
  { id: "design", label: "Design", color: "primary.500" },
  { id: "engineering", label: "Engineering", color: "neutral.600" },
];
const groups: WaffleChartGroup[] = [
  {
    id: "shared",
    label: "Shared team",
    description: "Linked to two priorities",
  },
  { id: "unlinked", label: "Unlinked team" },
];
const items: WaffleChartItem[] = [
  {
    id: "design-1",
    label: "Designer 1",
    categoryId: "design",
    groupId: "shared",
  },
  {
    id: "engineer-1",
    label: "Engineer 1",
    categoryId: "engineering",
    groupId: "shared",
  },
  {
    id: "engineer-2",
    label: "Engineer 2",
    categoryId: "engineering",
    groupId: "unlinked",
  },
];

<WaffleChart
  accessibilityLabel="Grouped resource pool"
  items={items}
  categories={categories}
  groups={groups}
/>;
```

`item.groupId` assigns each item to at most one supplied group. Put the shared team's two outgoing relationships in a caller-owned connection layer; keep each resource once in `items`. The example therefore has three cells in the whole pool, regardless of how many targets a group connects to. Group order follows `groups`. By default, item order within each group follows `items`; `itemOrder="category"` clusters each group's cells independently.

Items with no group or an unmatched `groupId` stay visible in the neutral `ungroupedLabel` bucket. An unlinked group is simply a group with no supplied relationship. Neither state establishes availability, spare capacity, or an error. Supplied empty groups retain their caption and zero count.

### Controlled cell order, columns, and density

Use `itemOrder` to choose input order or category clusters, `maxColumns` to limit columns, and `cellSize` with `gap` to tune density. The caller owns the controls and their state. Using the synthetic `items`, `categories`, and `groups` above:

```tsx
import { useState } from "react";
import { Select } from "@easypost/easy-ui/Select";
import type { WaffleChartItemOrder } from "@easypost/easy-ui/WaffleChart";

const densities = {
  dense: { cellSize: 16, gap: 2 },
  comfortable: { cellSize: 20, gap: 6 },
  spacious: { cellSize: 28, gap: 10 },
};

function ArrangedPool() {
  const [itemOrder, setItemOrder] = useState<WaffleChartItemOrder>("input");
  const [maxColumns, setMaxColumns] = useState(7);
  const [density, setDensity] = useState<keyof typeof densities>("comfortable");

  return (
    <>
      <Select
        label="Cell order"
        selectedKey={itemOrder}
        onSelectionChange={(key) =>
          setItemOrder(key === "category" ? "category" : "input")
        }
      >
        <Select.Option key="input">Input order</Select.Option>
        <Select.Option key="category">Group by category</Select.Option>
      </Select>
      <Select
        label="Maximum columns"
        selectedKey={String(maxColumns)}
        onSelectionChange={(key) => setMaxColumns(Number(key))}
      >
        <Select.Option key="4">4</Select.Option>
        <Select.Option key="7">7</Select.Option>
        <Select.Option key="12">12</Select.Option>
      </Select>
      <Select
        label="Density"
        selectedKey={density}
        onSelectionChange={(key) => setDensity(key as keyof typeof densities)}
      >
        <Select.Option key="dense">Dense</Select.Option>
        <Select.Option key="comfortable">Comfortable</Select.Option>
        <Select.Option key="spacious">Spacious</Select.Option>
      </Select>
      <WaffleChart
        accessibilityLabel="Arranged resource pool"
        items={items}
        categories={categories}
        groups={groups}
        itemOrder={itemOrder}
        maxColumns={maxColumns}
        {...densities[density]}
      />
    </>
  );
}
```

Category clustering uses category IDs, never color equality. It applies within each explicit group and the remainder bucket, leaving group membership and group order unchanged. Compact mode applies the chosen order to its flat item grid. Every arrangement keeps the same item IDs, counts, category-to-token mappings, draft and muted states, and supplied selection. Keep any controls outside a compact summary's link so the row remains one passive link.

The example below uses the same linked synthetic pool to show cells wrapping and connection endpoints following order, column, and density changes. Dense uses 16px cells and 2px gaps; Comfortable uses 20px and 6px; Spacious uses 28px and 10px. Interactive cells keep their minimum 24px pointer target in every density.

### Controlled selection, details, and category emphasis

Using the synthetic `items`, `categories`, and `groups` above:

```tsx
import { useState } from "react";
import type { WaffleChartSelection } from "@easypost/easy-ui/WaffleChart";

function ControlledPool() {
  const [selection, setSelection] = useState<WaffleChartSelection>(null);
  const [categoryId, setCategoryId] = useState<string | null>(null);

  return (
    <WaffleChart
      accessibilityLabel="Inspectable resource pool"
      items={items}
      categories={categories}
      groups={groups}
      selection={selection}
      onSelectionChange={setSelection}
      selectedCategoryId={categoryId}
      onCategorySelectionChange={setCategoryId}
      renderDetails={({ item, group, pinned, totalCount }) => (
        <div>
          {pinned ? "Pinned" : "Preview"}: {item?.label ?? group?.label}
          {item?.draft && " · Draft"}
          {" · "}
          {totalCount} items in the pool
        </div>
      )}
    />
  );
}
```

`selection` is `null`, `{ type: "item", id }`, or `{ type: "group", id }`. Pass `onSelectionChange` to accept controlled changes, or omit `selection` and use `defaultSelection` for local initial state. A controlled selection without `onSelectionChange` is read-only and does not show Clear selection. Stable IDs preserve selection when items move or reorder; selections absent from the latest supplied data are not rendered. A valid pinned selection takes precedence over transient focus and hover inspection. When unpinned, the latest pointer hover or keyboard focus interaction leads inspection without moving focus away from its control.

`onItemHoverChange`, `onItemFocusChange`, `onItemActivate`, and their `onGroupHoverChange`, `onGroupFocusChange`, `onGroupActivate` counterparts support linked views. Hover and focus callbacks receive the full supplied record, and `null` when the interaction leaves or is cleared. Hover inspection stays available while the pointer crosses the chart into its details, so the detail text can be hovered and selected without pinning. It clears when the pointer leaves the combined chart/details area or on Escape; entering another item or group updates it immediately. Activation callbacks receive the activated record; clicking the same selected target again requests a cleared selection. These callbacks do not require querying internal markup.

`renderDetails` receives the target, optional item and group, pinned state, and unchanged `totalCount`. Use it for caller-owned metadata, labels, and evidence. Exact inspection is visible in the chart's live detail region, rather than hidden in native `title` tooltips.

The legend always shows exact category counts. With `onCategorySelectionChange`, its entries become buttons that request a category ID or `null`; the caller supplies the result as `selectedCategoryId`. This emphasizes matching cells and dims the rest without removing cells or changing totals. `highlight` can additionally supply `itemIds`, `groupIds`, and `categoryIds` together to coordinate cells, group boundaries, and caller-owned edges. Highlight, selection, `draft`, and `muted` are independent supplied states.

### Keyboard, pointer, and touch inspection

Tab reaches group caption buttons and the current cell in the roving cell tab stop. Arrow Left/Right move between cells in displayed order; Arrow Up/Down use the current layout to reach the nearest visual row, then the closest column, including partial rows after wrapping. Home/End move to the first/last cell. Focus has a visible indicator and exposes the same exact details as pointer hover.

Enter, Space, a click, or a touch tap pins an item or group. A repeated activation unpins it; Clear selection or Escape dismisses pinned and transient inspection. Escape also requests that a controlled category highlight be cleared. Once dismissible chart state is cleared, Escape can reach an enclosing Modal or Drawer instead of being trapped by the chart. Controlled callbacks must update the corresponding props for those requests to take effect. Touch inspection does not depend on hover. Dismissing a focused detail control returns keyboard focus to the inspected cell or group caption, including pointer-exit dismissal of unpinned hover inspection. Data removal or moving a cell between groups clears transient inspection when its focused or hovered element is replaced; it does not resurrect stale inspection if that ID returns.

### Supported anchors for a connection layer

`onGroupAnchorsChange` supplies an array of `{ groupId, element, bounds }` for explicit groups in the default presentation. Join `groupId` to your own relationships; the same anchor can be the source of several edges. `element` is a supported public endpoint, and `bounds` contains `left`, `top`, `right`, `bottom`, `width`, and `height` in viewport CSS pixels. Consumers never need private class names or DOM selectors.

Use bounds directly in a fixed viewport-aligned connection layer. For an overlay in another coordinate system, convert the bounds to that layer's coordinates, accounting for its viewport origin, scrolling, and any scale. For example, an unscaled SVG whose coordinate origin matches its viewport rectangle uses `bounds.left - svgRect.left` and `bounds.top - svgRect.top`.

Anchors are measured after mount and data changes, and update after cell-order, column-limit, or density changes, resize, responsive wrapping, and scrolling when their geometry changes. The callback receives `[]` during cleanup so obsolete connectors can be removed. Use a stable callback such as a state setter; compact summaries do not expose group anchors. Change `layoutRevision` when caller-owned layout moves the chart without resizing it, such as opening an adjacent panel or changing an ancestor's position. This requests fresh viewport bounds.

The linked-groups story draws caller-owned connections from one shared group to two targets and highlights related cells, group, and edges together. Its composition reserves separate routing lanes outside the pool and target cards, including when the targets stack below the chart. Resize the story and scroll its page to check endpoint alignment.

### Unknown, empty, and responsive states

Unknown category IDs retain their cells and exact counts, use a neutral dashed marker, and show `Unknown category: <id>` in the legend and accessible item label. A missing mapping is never assigned the next category's color. Empty `items` show `emptyMessage` and an exact zero total; empty data does not imply an available pool. Applications should distinguish loading and failed queries in their surrounding UI instead of supplying an unexplained successful empty state.
