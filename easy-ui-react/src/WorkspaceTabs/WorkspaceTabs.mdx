# WorkspaceTabs

Controlled workspace views with pinned and closable tabs. Applications own the panels, selection policy, and close confirmation or persistence. Use `TabNav` for URL navigation, or `TabPanels` for integrated tab/panel composition.

## Usage

```tsx
import { WorkspaceTabs } from "@easypost/easy-ui/WorkspaceTabs";
import { useWorkspaceTabIds } from "@easypost/easy-ui/WorkspaceTabs";
```

Call `useWorkspaceTabIds` once per instance, then share it with `WorkspaceTabs` and your external panels. Keys must be unique across both lists and remain stable. Opaque keys such as `order/a` and `order_002fa` get distinct DOM IDs; separate hook calls isolate separate workspaces. Do not construct, sanitize, or parse the generated IDs.

The hook supports React 16.14, 17, 18, and 19. For server-rendered React 16/17 apps,
wrap the application in one React Aria `SSRProvider` on both the server and client,
as described in the package README. Import it with the same module format as Easy UI
and keep a single React Aria dependency version. React 18+ does not need this wrapper.

```tsx
// React 16/17: use this same root for server rendering and hydration.
import { SSRProvider } from "react-aria";

<SSRProvider>
  <App />
</SSRProvider>;
```

```tsx
import { useState } from "react";

function Orders() {
  const ids = useWorkspaceTabIds();
  const [selectedKey, setSelectedKey] = useState("overview");
  const [openTabs, setOpenTabs] = useState([
    { id: "order/a", label: "Order A" },
  ]);
  const pinnedTabs = [{ id: "overview", label: "Overview", count: 0 }];
  return (
    <>
      <WorkspaceTabs
        aria-label="Workspace views"
        ids={ids}
        pinnedTabs={pinnedTabs}
        openTabs={openTabs}
        selectedKey={selectedKey}
        onSelectionChange={setSelectedKey}
        onClose={(id) => {
          setOpenTabs((tabs) => tabs.filter((tab) => tab.id !== id));
          if (selectedKey === id) setSelectedKey("overview");
        }}
      />
      {[...pinnedTabs, ...openTabs].map((tab) => (
        <section
          key={tab.id}
          role="tabpanel"
          id={ids.panelId(tab.id)}
          aria-labelledby={ids.tabId(tab.id)}
          hidden={tab.id !== selectedKey}
          tabIndex={0}
        >
          {tab.label}
        </section>
      ))}
    </>
  );
}
```

## Props

<ArgTypes of={WorkspaceTabs} />

Each `WorkspaceTab` supplies `id`, string `label`, optional `count`, `isDisabled`, and `isClosable`. Pinned tabs never close. Open tabs close by default when `onClose` is supplied; set `isClosable={false}` on an item to suppress its close button. Disabled items cannot activate or close. `getCloseLabel` localizes the separate close buttons, whose default is “Close [label] tab”. Zero counts remain visible and part of the accessible tab name.

### Independent workspace IDs

opaque keys in another workspace does not reuse DOM IDs. Caller-supplied `ids`
remain supported; omitting them generates internal IDs for the bar.

### Manual activation and controlled removal

Left/Right arrows wrap focus across enabled tabs without changing selection. Home/End focus enabled endpoints; Enter/Space activate. Right/Left direction follows RTL layouts. Close buttons are separate buttons, never nested in a tab. Initial keyboard entry targets the selected enabled tab, or the first enabled tab. Tab from a focused tab reaches its close button when present. To close another view with the keyboard, arrow to its tab and press Tab to reach its close button; this does not activate the view.

The application must update `selectedKey` when its selected tab closes. A delayed controlled removal recovers focus to the next enabled tab at that position, then the preceding enabled tab, or the empty bar. It never changes selection or steals focus after the user leaves the bar.

For a single reused external panel, supply its ID with `panelId="order-panel"`, and set that panel's `aria-labelledby` to `ids.tabId(selectedKey)`. Keep the hook instance and keys stable. Give the tablist an `aria-label` or `aria-labelledby`.

### Overflow and long labels

The bar scrolls independently of the page. A focused tab or close control takes priority
when an external selection changes; when focus is outside the bar, the new selection is
revealed instead. Actual strip, item-size, or tab-order changes reveal the current focus
or selection using the same priority.
Unrelated parent updates preserve deliberate scrolling when focus is outside the bar. Long labels truncate visually while retaining their full accessible names and hover titles. Trailing content stays outside the tablist; keep actions compact in narrow workspaces.

Give the surrounding layout a shrinkable track when composing a workspace in CSS Grid,
for example `grid-template-columns: minmax(0, 1fr)`. This keeps the application-owned
panels and bar within the available width while the tab strip scrolls locally.

### Width transitions

Resize the workspace while navigating to verify selected/focused items remain revealed.
To check ordinary parent updates, focus the unrelated-update button, scroll the strip,
and update the parent without changing the workspace. The deliberate scroll stays put.
The parent-owned “Select overview (F2)” control also lets you change selection without
moving keyboard focus: focus a different tab or close button and press F2.
